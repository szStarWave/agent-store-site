## 4. 补齐策略与分类应对

各类条目的接入路径与技术方案存在本质差异：

| 分类层级 | 涉及条目 | 对应接入方案与动作约束 |
| --- | --- | --- |
| **既有可用** | 飞常准、东方财富妙想 | 本站已完成接入，无需额外动作 |
| **依赖引入新数据源** | 百度地图、快递100、高德地图、航班管家 | 仅存在于 ModelScope 广场；必须设计独立的数据管道与同步协议方可收录 |
| **社区第三方（建议暂缓）** | 同程搜索、携程系 3 项、京东金融 | 多由个人开发者聚合发布（如 `mako2026/...`），存在协议变更与服务可用性风险，不建议作为官方推荐引入 |
| **完全缺失** | T3出行、喜马拉雅、小米商城、哈啰出行、闲鱼 | 上游生态尚未建设，需等待厂商官方开源或接入 |

## 6. ModelScope 广场发布方身份鉴别规则

根据平台规范，可通过服务 ID 结构判定发布方属性与权威度：

| ID 命名范式 | 发布主体性质 | 典型实例 |
| --- | --- | --- |
| `@author/server_name` | 官方平台收录但尚未由所有者认领的镜像 | 高德地图 (`@amap/amap-maps`)、百度地图 (`@baidu-maps/mcp`)、飞常准 (`@variflight-ai/variflight-mcp`) |
| `user_name/server_name` | 经过厂商认证/开发者自提交的官方账号 | 快递100 (`kuaidi100/kuaidi100-mcp`)、航班管家 (`flightmanager/aviation-data-mcp`) |
| `personal_id/...` | 社区个人或非官方第三方发布（稳定性需独立评估） | `mako2026/...`、`valarmoes/...`、`dingtalk/...` |

- **检索匹配特性**：搜索接口执行模糊语义匹配，容易受词缀巧合干扰（如检索 `T3` 命中 `@t3ta/sql-mcp-server`，检索 `xiaomi` 命中 `xiamizhou1/MZMCP` 华云 OCR）。条目核对必须校验实际标题与所属领域，禁止仅依赖搜索结果计数。
- **速率限制门禁**：高频并发请求约 15 次后将触发 `429 Too Many Requests` 限流；批量请求建议设定 2.2 秒以上间隔并配合指数退避机制。

## 10. 架构约束与已知事项

- **技能上游空元数据警告**：6 个技能条目（`grill-me`、`handoff`、`mcp-builder`、`impeccable`、`web-access`、`skill-creator`）上游仅存在元数据而无实际内容，同步脚本会输出告警但不阻断构建。
- **分类维度缺失**：`connectors.json` 与 ModelScope 列表均未内置统一的类别枚举，本报告的分类维度取自灵感广场基准；若前端需要实现类别筛选，需在上游数据源补充声明或在前端建立映射词典。
- **全量无损透传原则**：前端目录页不执行 `visible_in` 或客户端版本过滤，对 228 项条目均予以展示，保证与上游数据源的真实镜像一致性。
- **异构数据源隔离原则**：ModelScope MCP 广场与本站当前采用的文件树镜像体系在数据结构、分发模型上存在根本差异，若引入需建立独立的接入体系，禁止直接混入现有 `market-source/`。
- **清单排序与 Locale 关联**：`_files.txt` 基于字符序排序，多语言环境构建可能产生行序微小变化，该特性不破坏镜像增量契约。
